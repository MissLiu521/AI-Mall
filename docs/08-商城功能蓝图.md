# AI Mall 功能蓝图（对标淘宝 / 京东 / 拼多多 / 抖音商城）

> 设计时间：2026-10-19
> 输入：现有项目（Node 22 + SQLite + Vue3 + uni-app，零第三方依赖）
> 目标：把四大平台的**有效模块**吸收进来，并在四件事上做得比它们更好——**信息透明、决策省力、售后可预期、AI 真办事**
> 约束：本地可运行可演示，不引入外部付费服务（真实支付/物流/短信除外，用等价模拟）

---

## 一、四大平台拆了什么

| 平台 | 真正的护城河 | 可复用的模块 | 它的代价（我们的机会） |
| --- | --- | --- | --- |
| **淘宝** | 商品供给极丰富、店铺生态 | 店铺分层、SKU 多规格、评价体系（含追评/晒单）、购物车按店分组、跨店满减、逛逛内容流 | 信息过载、同款比价困难、评价真假难辨 |
| **京东** | 自营 + 物流确定性 | 自营标识、211 限时达、物流轨迹节点、价保、以旧换新、PLUS 会员 | 价格不总是最低、第三方店铺服务参差 |
| **拼多多** | 价格心智 + 社交裂变 | 拼团、百亿补贴、限时秒杀、砍价、凑单、先用后付 | 套路感强、退款入口深、品质信任弱 |
| **抖音商城** | 内容即货架 | 短视频/图文挂商品、直播间、达人分销、兴趣推荐、评价带图 | 冲动消费后退货率高、缺少参数对比 |

**结论**：四家共同具备、且用户已经形成肌肉记忆的模块，我们必须有（否则"不像个商城"）；四家共同的**用户痛点**，正是我们的差异化切口。

## 二、我们的四条差异化原则

| 原则 | 具体做法 | 对比谁的短板 |
| --- | --- | --- |
| **信息透明** | 到手价拆解（标价 − 券 − 积分 − 满减 = 实付）每一分都列出来；规格实测表；库存语义化（"仅剩 3 件"而非"库存 3"） | 淘宝/拼多多的"券后价"要算半天 |
| **决策省力** | AI 比价（同品类参数对齐）、AI 凑单（差 12 元免邮时给方案）、AI 评价摘要（500 条评价压成 3 句话） | 京东参数页要自己横向对比 |
| **售后可预期** | 商品页直接显示"能不能退、几天、谁付运费"；退款时间轴显示"现在卡在谁那里"；退款驳回恢复原状态不打回 | 拼多多退款入口深、状态含糊 |
| **AI 真办事** | 客服不是问答机器人：能查订单、能发起退款、能推荐替代品、答不上来一键转人工落工单 | 四家客服都要排队等人工 |

## 五、计价引擎（唯一真相源）

```
行小计 = Σ(sku 单价 × 数量)
会员折扣 = 行小计 × (1 - 会员折扣率)          // 银卡 0.95 / 金卡 0.9
券优惠   = 满足门槛后按券规则计算（不超过剩余金额）
满减     = 跨店满 199 减 30 / 满 399 减 80（取最优一档）
积分抵扣 = min(积分余额/100, 剩余金额 × 30%)
运费     = 会员包邮 ? 0 : (小计 ≥ 99 ? 0 : 8)
实付     = 行小计 - 会员折扣 - 券优惠 - 满减 - 积分抵扣 + 运费
```

**关键约束**：结算页预览与真实下单必须调用**同一个函数**，避免"看到的价和付出的价不一样"。

## 七、验收标准（比"有功能"更严）

1. 结算页显示的实付金额，与订单 `total_cents` **逐分相等**（自动化断言）。
2. 任何营销优惠**不能把实付打到负数**；券用掉后状态即时变更，重复使用返回 400。
3. 秒杀库存与 SKU 库存联动扣减，超卖返回 `OUT_OF_STOCK`。
4. 拼团成团后批量把团员订单置为 `paid`；超时未成团自动退款。
5. 评价只能对**已完成且属于自己**的订单提交，一单一评。
6. 所有新增接口非法入参返回 400，不泄露 SQLite 错误。
