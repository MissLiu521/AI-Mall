# 05 · 多端架构（App / 微信小程序 / 支付宝小程序）

## 目标

一套移动端代码，编译到 H5（即"App 可直接用手机浏览器访问"）、微信小程序、支付宝小程序三个端，复用现有 `server` API，不复制业务逻辑。

## 技术选型：uni-app（Vue3 + TS + Vite）

| 备选 | 结论 |
| --- | --- |
| uni-app ✅ | 一套 Vue3 代码 → H5 / mp-weixin / mp-alipay / App；条件编译处理平台差异；生态成熟 |
| Taro | 同类能力，React 优先，本项目 Web 端是 Vue，统一心智成本更高 |
| 原生各写一份 | 三倍工作量，接口/组件无法复用，排除 |
| Flutter / RN | 产出原生 App 但不产出小程序，与"小程序"需求不符 |

## 请求层设计（`mobile/src/api/index.ts`）

```
BASE_URL =
  #ifdef H5      →  '/api'              （同源，vite 代理到 3001）
  #ifndef H5     →  http://<局域网IP>:3001/api   （小程序直连）
```

- 所有请求走 `uni.request` 封装，统一注入 JWT（`Authorization: Bearer`）与幂等键头
- 401 统一清 token，由页面级 `requireLogin()` 拦截跳登录页
- Token 存 `uni.getStorageSync`（H5 落 localStorage，小程序落 storage）

## AI 能力对齐

- 导购场景（免登录可用）：自然语言选品，走 `search_products` 等工具，回复含推荐理由
- 客服场景（需登录）：查订单、退货资格判定、发起退款，全部走工具调用；无工具直接回答会被限制
- 转人工：客服场景导航栏常驻「转人工」，提交问题描述 + 联系方式 → 落 `support_tickets` 工单 → 商家后台「人工工单」回复结单；同一会话重复提交返回 `duplicate: true`，不重复建单

## 地址表单（两端共用同一套逻辑）

`web/src/utils/address.ts` 与 `mobile/src/utils/address.ts` 内容完全一致（有测试保证），包含：

- **省市区数据**：`{web,mobile}/src/data/regions.json`，34 省 / 349 市 / 3116 区（约 48KB，打包进地址表单所在页面，gzip 后更小）；直辖市合并为「北京市 → 朝阳区」两层，港澳按「省 → 区」处理
- **智能识别 `parseAddress(text, tree)`**：整段文本拆出 姓名 / 手机号 / 省 / 市 / 区 / 详址；支持「张三138…广东省深圳市…」无分隔写法、`138-0013-8000` 带分隔手机号、省略「省/市」字的简称（广东深圳）、`收货人：/电话：` 标签、复合姓（欧阳/司马…）；识别不出的字段如实返回 `missing`，不硬编
- **必填校验 `validateAddress(draft)`**：姓名 1–30 字、手机号格式、省市区必选、详址 ≥5 字；返回 `{字段: 错误文案}`，两端红字提示共用这一份文案
- 级联选择：Web 用三个 `<select>` 联动，移动端用 `picker mode="multiSelector"`；改动省份时只清空不合法的市/区，不会覆盖已填好的值
- 工具轨迹 UI：每次回复可展开查看「调用了哪些工具 / 入参 / 耗时 / 是否成功」，与 Web 端一致
- 权限在服务端工具层校验（游客拿不到订单工具），前端仅做引导

## 平台差异处理

| 差异点 | 处理 |
| --- | --- |
| BASE_URL | 条件编译（见上） |
| 状态栏高度 | `pages/ai/ai` 自定义导航，`uni.getSystemInfoSync().statusBarHeight` 适配 |
| 底部安全区 | `env(safe-area-inset-bottom)` + `safeAreaInsets` |
| tabBar 图标 | 文字 tabBar（避免二进制资源），后续可补 iconfont |
| 合法域名 | 小程序开发工具勾选"不校验合法域名"；生产需 HTTPS + 后台配置 |
